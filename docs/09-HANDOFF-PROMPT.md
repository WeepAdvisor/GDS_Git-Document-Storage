# 09 — Промпт для исполнителя (Grok)

Скопировать в начало сессии реализации.

---

Ты реализуешь macOS-приложение **GitDocumentStorage** в этом репозитории. Перед любым действием прочитай:
`.cursor/rules/*.mdc`, `docs/00-PLAN.md`, `docs/01-ARCHITECTURE.md`, затем документы, относящиеся к текущей фазе.

Правила:
1. Работай строго по фазам из `docs/00-PLAN.md`. Сейчас фаза: **0**. Не переходи к следующей, пока не выполнены критерии приёмки текущей, и не спросив подтверждения.
2. После каждого изменения кода запускай `make build` и `make test`. Красная сборка — не коммить.
3. Не меняй архитектурные решения из `docs/06-DECISIONS.md`. Если считаешь, что нужно — опиши проблему и предложи новый ADR, но не реализуй до согласования.
4. Не добавляй зависимостей кроме `GRDB.swift`.
5. Контракты (`RemoteRepository`, `ItemStore`, `TokenStore`, модели в `SyncCore`) уже есть в `Packages/GitDocsKit/Sources` — реализуй их, а не придумывай новые. Расширять можно, менять сигнатуры — с обновлением `docs/01-ARCHITECTURE.md`.
6. Любая работа с File Provider — сверяйся с `.cursor/rules/fileprovider.mdc`. Любая работа с GitHub — с `docs/04-GITHUB-API.md`.
7. Каждая задача = коммит с префиксом `P<фаза>:`.
8. Если наблюдаешь поведение системы, не совпадающее с документацией проекта, запиши его в `docs/08-OPEN-QUESTIONS.md` → «Наблюдения».
9. В конце каждой фазы: пройди ручные сценарии `docs/07-TESTING.md` для этой фазы, отчитайся чек-листом «✅/❌ + как воспроизвести».
10. Для запуска нужен `Config/Local.xcconfig` (см. `Config/Local.xcconfig.example`). Если его нет — попроси пользователя указать `DEVELOPMENT_TEAM` и `GITHUB_OAUTH_CLIENT_ID`.

Начни с фазы 0: прочитай план, выполни `make generate && make build && make test`, устрани проблемы, добейся появления папки «Demo» в Finder.
