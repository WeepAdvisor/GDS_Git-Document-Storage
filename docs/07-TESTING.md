# 07 — Тестирование

## 1. Уровни

| Уровень | Где | Как запускать | Сеть |
|---|---|---|---|
| Unit (пакет) | `Packages/GitDocsKit/Tests` | `make test` / `swift test` | нет (`MockURLProtocol`, `MockRemoteRepository`) |
| Интеграция с GitHub | те же тесты с префиксом `Live…` | `GDS_TEST_TOKEN=… GDS_TEST_REPO=owner/repo swift test --filter Live` | да, отдельный тестовый репо |
| Ручная приёмка Finder | сценарии ниже | вручную по чек-листу | да |

Тестовый репозиторий: приватный, пустой, создаётся вручную. Интеграционные тесты работают в подпапке `_gds_tests/<uuid>/` и удаляют её в `tearDown`.

## 2. Моки

- `MockURLProtocol`: регистрация ответов по `(method, path)` с заголовками (`ETag`, `x-ratelimit-*`, `retry-after`), счётчик вызовов, запись тел запросов (для проверки состава `tree[]`, `additions[]`).
- `MockRemoteRepository: RemoteRepository`: in-memory «сервер»: словарь path→(sha, bytes), `head`, журнал коммитов, флаг `rejectNextCommitAsNotFastForward`, возможность «чужого» коммита между вызовами (`simulateRemoteChange`).
- `InMemoryTokenStore`, `TemporaryDomainStore` (SQLite в temp).

## 3. Ручные сценарии приёмки

### T0 — Каркас
- T0.1 Папка «Demo» видна в Finder, `README.txt` открывается.

### T3 — Чтение
- T3.1 Добавить репо с ~1000 файлов → дерево полное, папки раскрываются, размеры/даты показаны.
- T3.2 Открыть `.docx`, `.pdf`, `.png`, 50 MB-файл → скачивание с прогрессом Finder, открытие.
- T3.3 Веб-коммит: добавить файл → в Finder ≤ 10 с. Изменить → версия обновилась (материализованный файл перекачан). Удалить → исчез. Переименовать → переименован (без исчезновения/появления).
- T3.4 Quit приложения → баннер Finder; `cat` нескачанного файла → ошибка; запуск → снова работает.
- T3.5 Сон Mac 5 мин → пробуждение → изменения подтянулись.

### T4 — Запись
- T4.1 `echo hi > file.txt` в папке → коммит ≤ 5 с, сообщение `Add file.txt`.
- T4.2 Сохранение из TextEdit (несколько раз подряд за 5 с) → один коммит.
- T4.3 Сохранение из Pages/Word (атомарное) → один коммит, без temp-файлов в репо.
- T4.4 Копирование папки 300 файлов/20 MB → ≤ 3 коммита, ≤ 60 с, все значки «синхронизировано».
- T4.5 Переименование папки с 50 файлами → 1 коммит, 0 `POST git/blobs` в логах.
- T4.6 Дублирование файла (Cmd+D) → 1 коммит, без загрузки blob.
- T4.7 Удаление папки → 1 коммит.
- T4.8 Создание пустой папки → `.gitkeep` в репо; у второго клиента папка появилась.
- T4.9 `.DS_Store` появился локально → в репо его нет.
- T4.10 Файл 150 MB → значок ошибки + уведомление «too large for GitHub».
- T4.11 Пустой репозиторий → первый файл создаётся, дальше обычный режим.
- T4.12 Read-only репо → Finder не даёт писать (замок), drag&drop отклоняется.

### T5 — Конфликты (два Mac или Mac + веб)
- T5.1 Оба правят `a.txt` в пределах 10 с — `lastWriterWins`: содержимое последнего, уведомление у первого, предыдущая версия в истории.
- T5.2 То же в `keepBoth` — conflicted copy у обоих, оригинал = чужая версия.
- T5.3 Mac1 удаляет `a.txt`, Mac2 одновременно правит → `a.txt` вернулся с правкой у обоих.
- T5.4 Mac1 переименовывает `a→b`, Mac2 правит `a` → `b` содержит правку.
- T5.5 Веб: создать `README.md` рядом с существующим `Readme.md` → расширение живо, второй файл с суффиксом.
- T5.6 Имя с диакритикой (`Отчёт é.docx`) с Mac → в GitHub NFC, второй Mac показывает корректно, без дублей.

### T6 — UI
- T6.1 Чистый пользователь проходит онбординг за ≤ 2 мин.
- T6.2 Два аккаунта, два репо; sign out первого → его папка отключена с объяснением; sign in обратно → работает.
- T6.3 Отзыв токена на GitHub → в течение минуты «Sign in again».
- T6.4 Quit при незавершённой загрузке → диалог «Finishing upload», после завершения — выход.

### T7 — Надёжность
- T7.1 Репо 20 000 файлов → initial load ≤ 30 с, память расширения < 200 MB.
- T7.2 1000 файлов по 10 KB → ≤ 5 коммитов, ≤ 3 мин, без 403.
- T7.3 50 файлов по 20 MB → без 403, прогресс в меню.
- T7.4 `kill -9` расширения во время батча → после перезапуска батч доезжает, один коммит.
- T7.5 Отключить Wi-Fi на 2 мин во время записи → после восстановления всё доехало.
- T7.6 30 мин активной работы → Leaks чистый.

## 4. Что считать регрессией

Любой упавший unit-тест; любое падение расширения (`Console.app` → crash reports `GitDocumentStorageFileProvider`); любой коммит в репо с содержимым из ignore-list; любой force-push (не должно существовать по коду).
