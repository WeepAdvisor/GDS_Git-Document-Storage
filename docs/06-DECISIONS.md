# 06 — Архитектурные решения (ADR)

Формат: контекст → решение → последствия. Новые решения добавлять в конец, старые не редактировать (помечать superseded).

## ADR-001. Интеграция с Finder через File Provider, а не FUSE/FSKit/WebDAV

**Контекст.** Нужна папка в Finder, ведущая себя как сетевая, без kext'ов и «понижения безопасности».

**Рассмотрено.**
- macFUSE — kernel extension, на Apple Silicon требует снижения политики безопасности. Неприемлемо для «просто поставил и работает».
- FUSE-T (NFS-прокси) — сторонний компонент, не Apple, нестабильная поддержка.
- FSKit (macOS 15.4+) — юзерспейс-ФС, но заточен под блочные устройства, монтирование через `mount -F`, нет push-уведомлений Finder, мало production-примеров.
- Локальный WebDAV/NFS-сервер + автомонтирование — проще всего, но Finder не узнаёт об удалённых изменениях без поллинга клиента ОС, агрессивное кэширование `webdavfs`, нет значков синхронизации.
- **File Provider (Replicated)** — Apple-сanctioned для облачных хранилищ; сайдбар, значки состояния, dataless-файлы, push обновлений (`signalEnumerator`), встроенная обработка конфликтов версий, никаких прав администратора.

**Решение.** `NSFileProviderReplicatedExtension`.

**Последствия.** Нужен Team ID (App Groups), песочница, отдельный процесс расширения, отладка через `fileproviderd` логи. Семантика «папка недоступна без приложения» реализуется `disconnect/reconnect` + liveness-проверкой (см. ADR-005).

## ADR-002. Транспорт — GitHub API (REST Git Data + GraphQL), без локального клона и libgit2

**Контекст.** Нужно читать/писать файлы в репозиторий GitHub. Классика — клон + libgit2 push/pull/merge.

**Рассмотрено.**
- `libgit2` через SwiftGit2/xcframework — нативная зависимость (OpenSSL/libssh2), сборка под arm64/x86_64, лицензии, локальный клон (двойное место: клон + кэш File Provider), собственная логика merge.
- `/usr/bin/git` — требует Xcode CLT у пользователя; шелл-команды из песочницы расширения проблемны.
- **GitHub API**: `git/trees?recursive=1` (дерево), `git/blobs/{sha}` raw (чтение), `compare` (дифф), GraphQL `createCommitOnBranch` (атомарный коммит множества файлов с `expectedHeadOid`), REST `git/blobs|trees|commits|refs` (большие файлы, переименования без перезаливки).

**Решение.** API-only. `expectedHeadOid` даёт оптимистическую блокировку — ровно семантика «последний сохранивший выигрывает, но мы заметили гонку».

**Последствия.**
- Нет оффлайна (и не требуется — сетевая папка).
- Лимиты: 5000 req/ч primary на токен; secondary — 900 points/мин на эндпоинт (мутация = 5 points ⇒ ≤ 180 мутаций/мин), «80 content-generating/мин, 500/ч». Массовая заливка тысяч файлов медленная (минуты). Смягчение: батчинг в один коммит через GraphQL, лимитер, прогресс в меню.
- Файл > 100 MB — невозможно (ограничение GitHub). LFS — вне v1.
- Коммиты через GraphQL подписаны GitHub («Verified»), автор — пользователь токена.
- Абстракция `RemoteRepository` позволяет позже добавить реализацию на libgit2/других хостах.

## ADR-003. Аутентификация — GitHub OAuth App + Device Flow, fallback на PAT

**Контекст.** Максимально простая авторизация, несколько аккаунтов, без своего сервера.

**Рассмотрено.**
- OAuth Web Flow — нужен redirect/URL-схема и client secret в приложении (утечка).
- GitHub App + Device Flow — тонкие права (contents RW), но токены истекают через 8 ч (refresh-токены), установка App в каждую организацию — лишний шаг для «обычного пользователя».
- PAT вручную — пользователь должен понимать scopes.
- **OAuth App + Device Flow** — секрет не нужен (только публичный Client ID), токен не истекает, пользователь видит 8-значный код и подтверждает в браузере. Scope `repo`.

**Решение.** Device Flow как основной путь; «Paste a token» как запасной (fine-grained PAT с Contents: Read/Write). Один OAuth App регистрирует владелец проекта (см. `docs/05`).

**Последствия.** Scope `repo` широкий (доступ ко всем репо аккаунта) — честно сказать в UI. Для организаций с SAML SSO токен нужно авторизовать на странице SSO — показываем подсказку, когда API возвращает `X-GitHub-SSO`.

## ADR-004. Один репозиторий = один домен File Provider

**Контекст.** Нужно несколько папок.

**Решение.** `NSFileProviderDomain(identifier: <UUID репо-конфига>, displayName: <имя папки>)` на каждый репозиторий. Каждый домен — отдельная папка в сайдбаре и отдельный `store.sqlite`.

**Последствия.** Изоляция сбоев, независимые anchors/очереди. Переименование папки в настройках = `remove` + `add` домена с новым displayName (или `NSFileProviderManager` не умеет rename → документировано в плане).

## ADR-005. «Не запущено — недоступно» через disconnect + liveness-гард (мягкий режим по умолчанию)

**Контекст.** Расширение запускается системой независимо от приложения.

**Решение.** На выходе приложения — `disconnect(.temporary)` после сброса очереди; на старте — `reconnect()`. Расширение дополнительно проверяет живость приложения перед сетевыми операциями и возвращает `.serverUnreachable`. Строгий режим (`remove/add` домена) — опционально.

**Последствия.** Данные в кэше не теряются при краше; пользователь видит понятный баннер Finder. Строгий режим теряет материализованный кэш при каждом выходе.

## ADR-006. Конфликты: политика по умолчанию — «последняя запись побеждает» + архивная копия в истории git

**Контекст.** Пользователь просит поведение сетевой папки (SMB): без диалогов, последний сохранивший перезаписывает. В отличие от SMB у нас есть история git — перезаписанная версия не теряется.

**Решение.** Политика `ConflictPolicy` конфигурируема per-repo: `.lastWriterWins` (по умолчанию, см. `docs/08` Q4) и `.keepBoth` (Dropbox-style «conflicted copy»). В любом случае удалённое «удалить» против локального «изменить» → локальная версия побеждает (файл воскресает), как в Dropbox/OneDrive.

**Последствия.** В `lastWriterWins` возможна тихая перезапись чужих правок (видно в истории GitHub и в «Recent activity» меню). В `keepBoth` папка засоряется копиями, но ничего не перезаписывается.

## ADR-007. Хранилище состояния — SQLite через GRDB.swift

**Контекст.** Нужны стабильные идентификаторы, change log, очередь операций, доступ из двух процессов.

**Решение.** GRDB (WAL, миграции, типобезопасные запросы). Core Data отвергнут из-за сложности межпроцессной работы и миграций; plain `sqlite3` — слишком много ручного кода.

## ADR-008. Пустые папки — через скрытый файл `.gitkeep`

**Контекст.** Git не хранит пустые каталоги; пользователь ожидает, что созданная папка появится у других.

**Решение.** При создании пустой папки коммитим `<dir>/.gitkeep` (0 байт). Файл скрыт от пользователя (dotfile, Finder прячет). При появлении в папке других файлов `.gitkeep` оставляем (чтобы не плодить коммиты).

## ADR-009. Проект генерируется XcodeGen, зависимости — SPM

**Решение.** `project.yml` — источник истины; `.xcodeproj` в git не хранится. Общий код — локальный SPM-пакет `Packages/GitDocsKit`, тестируемый `swift test` без Xcode-симуляторов.
